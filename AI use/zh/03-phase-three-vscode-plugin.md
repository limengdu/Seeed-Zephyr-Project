# 阶段 3: VS Code 产品体验

## 1. 目标

阶段 3 把仓库里的示例、项目、metadata 和验证证据变成 VS Code 内的开发者体验。

插件是 XIAO + Grove Zephyr 工作的发现和项目助手。

一句话总结: 阶段 3 让仓库里的验证内容能在 VS Code 中被看见、搜索、配置并生成项目。

## 2. 产品定位

推荐产品名:

```text
Seeed XIAO Zephyr Assistant
```

它应帮助用户:

- 浏览支持的 XIAO 开发板
- 浏览 Grove 模块
- 按开发板、模块、能力和验证状态浏览示例
- 浏览完整项目
- 预览接线和配置
- 从仓库示例/模板创建新项目
- 通过官方 Zephyr 工具构建
- 理解 XIAO/Grove 特定错误
- 准备符合贡献要求的示例

它的职责是:

- 发现 XIAO 和 Grove 内容
- 浏览示例和项目
- 展示验证状态
- 预览接线和配置
- 从仓库资产创建项目
- 执行贡献检查
- 将 build、flash、monitor 和 debug 交给官方 Zephyr 工具

一句话总结: 插件是进入 XIAO + Grove Zephyr 示例/项目生态的引导入口。

## 3. 用户旅程

### 步骤 1: 选择起点

第一个界面应提供:

- 浏览示例
- 浏览项目
- 从开发板/模块创建
- 打开已有生成项目
- 验证贡献

一句话总结: 用户可以从示例、项目、硬件或贡献检查开始。

### 步骤 2: 浏览或选择硬件

插件展示开发板和模块时应包含:

- 验证状态
- 支持能力
- 可用示例
- 已知问题
- 推荐 Zephyr 版本

一句话总结: 发现内容和生成项目一样重要。

### 步骤 3: 选择示例或项目

用户可以按以下条件筛选:

- 开发板
- Grove 模块
- 接口
- 能力
- 扩展板
- build-only 或 hardware-tested 状态

一句话总结: 示例和项目是 UI 的一等对象。

### 步骤 4: 预览详情

插件展示:

- README 摘要
- 构建命令
- board target
- 所需硬件
- 接线图
- 预期串口输出或行为
- 验证证据

一句话总结: 用户在创建或构建前就应知道会发生什么。

### 步骤 5: 创建或打开项目

插件调用 CLI，从已知示例或模板复制/生成标准 Zephyr 项目。

一句话总结: 生成项目来自仓库资产。

### 步骤 6: 交给官方工具

build、flash、monitor 和 debug 应尽量交给官方 Zephyr 工具。插件负责 XIAO/Grove 特定的发现、
预览和项目创建流程。

一句话总结: 插件负责 Seeed 特定的发现和项目创建，官方工具负责通用 Zephyr 工具链。

## 4. MVP 范围

MVP 应包含:

- 示例浏览器
- 项目浏览器
- 开发板/模块/能力筛选
- 验证状态标记
- 所选示例的接线预览
- 从少量示例创建项目
- CLI 集成
- 官方 Zephyr 扩展交接

一句话总结: MVP 证明用户能浏览、使用并基于验证过的仓库内容创建项目。

## 5. 成功标准

阶段 3 成功条件:

- 用户能比手动搜索更快找到相关示例
- 用户能从已验证示例创建项目
- 生成项目能通过官方 Zephyr 工具构建
- 验证状态可见且易懂
- 接线图与真实硬件一致
- 贡献检查可访问
- 早期用户能比手动 Zephyr 设置更顺利完成第一个 XIAO + Grove Zephyr 项目

一句话总结: 成功意味着用户能更低摩擦、更有信心地从发现内容走到固件运行。

## 6. 未来扩展

MVP 之后:

- 网页兼容性矩阵
- 网页示例浏览器
- 更完整的项目画廊
- AI 辅助示例选择
- AI 辅助错误解释
- PlatformIO 项目输出
- 高级低功耗模板
- BLE、Wi-Fi、MQTT、Home Assistant 项目

一句话总结: 插件能成长，是因为它站在经过验证的内容目录之上。
