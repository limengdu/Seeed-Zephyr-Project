# 入门和分发设计

## 1. 入门目标

入门从用户想得到的结果开始，环境搭建只是其中一步。用户旅程应是:

```text
找到示例 -> 构建示例 -> 烧录示例 -> 理解示例 -> 修改示例 -> 贡献回来
```

环境搭建负责准备工具链，然后把用户指向仓库里的示例和项目。

一句话总结: 入门应尽快把用户带到本仓库的示例和项目。

## 2. 用户入口

仓库应支持四种入口:

- 开发板优先: "我有 XIAO ESP32C6，可以跑什么？"
- Grove 优先: "我有 Grove AS5600，有哪些示例？"
- 能力优先: "我需要 I2C、BLE、Wi-Fi、ADC、display 或 low power。"
- 项目优先: "我想要完整的 sensor/display/wireless 项目。"

一句话总结: 用户从硬件或意图开始。

## 3. Setup 层

Setup 脚本应:

- 安装或检查 Zephyr 工具
- 准备 Zephyr workspace
- 在需要时获取 blobs
- 打印下一条本仓库 example/project 命令

它们应把用户指向下一条本仓库示例或项目命令。

一句话总结: setup 打开门，并指向本仓库内容。

## 4. 分发层级

| 层级 | 目的 | 用户操作 |
| --- | --- | --- |
| L1 setup scripts | 准备本地工具链 | 运行一个脚本 |
| L2 example build scripts 或 CLI | 构建仓库内容 | 构建选定示例 |
| L3 project generator | 从已知资产创建自定义项目 | 选择硬件和来源资产 |
| L4 VS Code plugin | 可视化浏览和创建 | 选择、预览、创建 |

一句话总结: 每一层都应围绕示例和项目降低摩擦。

## 5. 贡献入门

外部贡献者应能:

1. 选择示例/项目类别
2. 复制已文档化的结构
3. 运行本地验证
4. 记录构建或硬件证据
5. 提交维护者可预测审查的贡献

一句话总结: 贡献入门也是产品入门的一部分。

## 6. 实施优先级

1. 先让至少一个仓库示例能从项目根目录构建。
2. 增加构建示例的脚本或 CLI 命令。
3. 增加贡献文档。
4. 改善平台 setup。
5. 在示例存在后，再增加 manifest/container/plugin 层。

一句话总结: 内容第一，工具第二， polish 第三。
